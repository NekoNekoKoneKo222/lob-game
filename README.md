# TSG Corporation

Lobotomy Corporation に影響を受けた施設管理シミュレーションゲーム。
TypeScript + Canvas によるデータ駆動設計、JSONのみでのMOD拡張に対応しています。

## 遊び方(起動方法)

`fetch()` でJSONデータを読み込むため、**ローカルサーバー経由で開く必要があります**
(`file://` で直接開くとブラウザのセキュリティ制限でデータが読み込めません)。

このフォルダで以下のいずれかを実行してください。

```bash
# Python がある場合
python3 -m http.server 8000

# Node.js がある場合
npx serve .
```

起動後、ブラウザで `http://localhost:8000/` を開いてください。

## ゲームの流れ

1. **朝**: 職員の雇用・配属を確認する
2. **昼**: 異常存在へ作業(本能/洞察/愛着/抑圧)を指示し、エネルギーを獲得する
3. **夕方**: 高危険度イベントが抽選される(停電・情報汚染・集団パニック等)
4. **夜**: 特殊イベントが抽選される
5. 「次のフェーズへ」ボタンで進行。夜の次は翌日の朝になり、職員の療養・
   カウンターの自然減少・研究の消費・セフィラ解放判定・オートセーブが行われる

収容中の異常存在のQliphothカウンターが0になると**収容違反**が発生します。
収容違反中は右パネルの職員チェックボックスから「鎮圧命令」を出すと、
リアルタイム(0.9秒ごとのtick)で戦闘が進行します。

E.G.O装備は該当する異常存在のカードから「抽出」でき、職員カードのプルダウンから
装備できます。研究で「E.G.O強化研究」を完了すると改造要素が使えるようになります
(現状は`systems/ego.ts`の`modifyWeapon`をコンソール等から呼ぶ想定の土台実装です)。

「未知の存在を調査する」ボタンで、コンセプト×恐怖×願望×都市伝説×動物×機械の
組み合わせからオリジナル異常存在を生成できます。

Day50で全異常存在が同時活性化、Day100で終末イベントが開始されます。
条件(生存職員5名以上・エネルギー500以上・Day100到達)を満たすと
「終焉の日」に挑戦して真エンディングを迎えられます。

## セーブ/ロード

- 右上「セーブ (JSON)」でセーブデータをダウンロードできます。
- 「ロード」でJSONファイルを読み込めます。
- 20秒ごと、およびタブを閉じる際に `localStorage` へ自動セーブされます。

## ディレクトリ構成

```
index.html          エントリーHTML
styles.css           ダークテーマのスタイル
src/                 TypeScriptソース(モジュール化構成)
  types.ts           全データ型定義
  dataLoader.ts       JSON読み込み・MODマージ
  rng.ts              シード付き乱数
  systems/            ゲームロジック(職員/作業/収容違反/E.G.O/研究/イベント/生成/セーブ)
  ui/                  DOM描画・Canvas施設マップ
  main.ts              エントリーポイント・ゲームループ
dist/                 コンパイル済みJS(ブラウザはこちらを読み込む)
data/                 本体のゲームデータ(JSON)
mods/                 MOD用フォルダ。manifest.json に列挙したJSONが自動読込される
```

## MODの追加方法

1. `mods/` フォルダに新しいJSONファイルを作成する
   (`mods/example_mod.json` を参考にしてください)。
2. `mods/manifest.json` の `"mods"` 配列にファイル名を追加する。
3. サーバーを再起動(またはリロード)すると自動的に読み込まれます。

`file://` で直接開いている場合など `fetch` が使えない環境では、
右パネルの「MOD JSONを読み込む」ボタンからファイルを手動選択して
その場で読み込むこともできます。

MODで追加できる項目: `abnormalities`(異常存在) / `weapons`(E.G.O武器) /
`armors`(E.G.O防具) / `gifts`(ギフト) / `jobs`(職員職業) / `research`(研究) /
`sephirah`(セフィラ) / `events`(イベント) / `themes`(UIテーマ) /
`generatorParts`(オリジナル異常存在生成パーツ)。
IDが本体データと重複した場合はMOD側の内容で上書きされます。

## 新しい異常存在を追加する例

`data/abnormalities.json` の配列に以下のようなオブジェクトを追加するだけです
(コード変更は不要):

```json
{
  "id": "my_new_abnormality",
  "name": "自作の異常存在",
  "risk": "TETH",
  "damageAttr": "BLACK",
  "maxCounter": 4,
  "workAffinity": { "instinct": 40, "insight": 40, "attachment": 40, "repression": 40 },
  "description": "説明文",
  "breachDanger": 20,
  "workDamage": { "hp": 8, "sanity": 8 },
  "egoReward": { "giftIds": ["gift_soft_slumber"] }
}
```

## 実装済み / 簡易実装の範囲について

一通り遊べる状態のプレイアブル実装として、以下を実装しています。

- 職員(能力値/経験値/ランク/HP/精神力/死亡・精神崩壊)
- 作業指示システム(本能・洞察・愛着・抑圧、成功率計算、成功/失敗の結果反映)
- Qliphothカウンターと収容違反の発生・自然減少
- リアルタイム(tick制)の収容違反鎮圧戦闘
- E.G.O武器/防具/ギフトの抽出・装備・簡易改造
- 研究システム(前提研究・エネルギー投入・完了効果)
- 昼夜システム(朝/昼/夕方/夜)と災害・特殊イベントの抽選
- セフィラの日数解放
- オリジナル異常存在生成
- 部署システム(6部署・部長任命の土台)、職員ランクと上位ランク特殊能力
  (指揮官/処刑人/医療班)
- Day50同時活性化・Day100終末イベント・真エンディング条件判定
- JSON完全データ駆動 + MOD自動読込 + セーブ/オートセーブ

以下は土台のみ実装し、素材の量やイベント本数は最小限にしてあります
(JSONを追加するだけで拡張できる設計です)。

- E.G.O改造UIは未接続(ロジックは`systems/ego.ts`にあるため、
  ボタンを追加すれば接続できます)
- 「終焉の日」は演出込みの専用マルチフェーズ戦闘ではなく、条件判定のみ
- 施設マップはリアルタイムの職員/異常存在の移動アニメーションではなく、
  収容違反中の部署を点滅表示する簡易版です
